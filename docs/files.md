# punch-craft-jianying · 文件说明

> 项目根目录 `punch-craft-jianying/`。装好依赖后，**运行环境约占 200 MB**；素材占多少取决于你自己的回放（**仓库里不含任何视频**）。

这个文件夹里只有 4 类东西：**你双击的入口**、**干活的代码**、**看的文档**、**跑出来的产物**。下面按这个顺序说清楚每个文件是干什么的、能不能删、哪些不该上传。

---

## 一、你日常只需要碰这 4 个文件

| 双击这个 | 会出现什么 | 什么时候用 |
|---|---|---|
| **`install.bat`** | 建虚拟环境、装依赖，只在**第一次**跑一次 | 刚 clone 下来、或换了台电脑 |
| **`start.bat`** | 黑窗口 + 浏览器打开 `127.0.0.1:8765` | **平时都用这个**。拖视频、拖 SRT、点句子、选版式、点生成，草稿直接出现在剪映里 |
| **`start-cli.bat`** | 黑窗口里一问一答 | 网页打不开时的退路；也可以把视频直接拖到图标上 |
| **`fix-audio.bat`** | 自动修一次退出 | **只在草稿完全没声音时用**（把写坏的音量关键帧删掉，换回剪映原生淡入淡出） |

其余文件都不需要主动打开。

## 二、代码（不用改，知道谁管什么就行）

| 文件 | 行数 | 作用 | 什么时候会碰它 |
|---|---|---|---|
| `gui.py` | 732 | 网页界面的服务端：接上传、列句子、收参数、调 `slice_by_text`、回传预览图。只监听本机 `127.0.0.1`，不联网 | 想加界面按钮时 |
| `slice_by_text.py` | 632 | **核心流水线**：读 SRT → 按编号取句 → 算切点 → 逐段剪切 → 拼成一条时间轴 → 交给 `make_draft` 建草稿。命令行也在这里（`build` 子命令） | 想改剪辑逻辑时 |
| `make_draft.py` | 508 | **草稿与版面**：1080×1920 画布、背景模糊轨、主视频位置、字幕样式、标题、淡入淡出、转场、推近。**顶部参数区就是全部可调项** | 想调字号、位置、模糊强度时 |
| `suggest.py` | 405 | **配乐清单生成器**：按时间轴产出 BGM 三套方案、音效搜索词与音量、花字文案与样式、5 条标题 + 封面大字。也负责情绪识别（决定爆点配什么音效） | 想改建议话术时 |
| `clean_subs.py` | 192 | **抹掉画面里烧死的原字幕**：自动认出字幕横带（纵向 83%–90% 那一层），用 ffmpeg `delogo` 取周围像素原位补平。**不改画面尺寸、不裁切** | 换一部原片、字幕位置不同时 |
| `markers.py` | 117 | **施工标记**：把「第几秒该放什么音效」做成一段静音 wav，**文件名就是提示内容**，摆到时间轴独立音轨上，画面完全看不见 | 想改提示写法时 |
| `preview.py` | 149 | **版面预览图**：不开剪映就能看到「标题/画面/字幕」的相对位置，检查字挡不挡脸 | 想改预览渲染时 |
| `fix_audio.py` | 210 | `fix-audio.bat` 背后的实现：读草稿的 `.backup/*load.bak` 明文快照，删音量关键帧、写回原生淡化 | 一般不用动 |
| `wizard.py` | 140 | 命令行问答式向导（`start-cli.bat` 调它） | 不用动 |
| `gen_demo.py` | 49 | 造一段 15 秒假素材（`demo/`）用来验证流程没坏 | 只做自检时 |

> 依赖关系：`gui.py` → `slice_by_text.py` →（`make_draft.py`、`clean_subs.py`、`markers.py`、`suggest.py`、`preview.py`）。改 `make_draft.py` 顶部的参数会影响所有入口。

## 四、产物（`preview/`，每次生成都会往里加东西）

| 文件 | 是什么 | 怎么用 |
|---|---|---|
| `<草稿名>.jpg` | 该草稿的**版面预览图**（1080×1920 合成图） | **发之前扫一眼**，确认标题 / 画面 / 字幕三者不打架 |
| `<草稿名>-配乐清单.html` | 这次切片的**作业清单**：BGM 三套方案 + 每个时间点放什么音效、搜什么词、多少音量 + 花字文案 + 5 条标题 + 封面大字 | **剪映里精剪时对着它做**，浏览器打开就行 |

每点一次「生成」，就会新增一对。**草稿定稿后，之前废案的图可以直接删**，不用留。

> 这两样都是本地产物，`.gitignore` 已把整个 `preview/` 排除，不影响上传。

## 五、素材（`uploads/`，注意别乱删）

下表以**一条 5 分钟、约 370 MB 的回放**为例，实际体积看你自己的片子。

| 文件 | 典型大小 | 作用 | 能删吗 |
|---|---|---|---|
| `<你的回放>.mp4` | 约 370 MB | 原始直播回放（输入） | 能，但删了以后想重剪要重传 |
| `<你的回放>.srt` | 几十 KB | 剪映识别后导出的字幕（输入） | 别删，体积很小，重导很麻烦 |
| `_clean/<你的回放>-clean.mp4` | 约原片一半 | 抹掉原字幕后的中间产物 | **不能删** —— 草稿的主轨道指向它，删了剪映里会显示素材丢失 |
| `_markers/*.wav`（每个提示一个 + 1 个底座） | 不到 1 MB | 施工标记的静音占位音频 | **不能删** —— 同样被草稿引用 |

> **关键规则**：`_clean/` 和 `_markers/` 里的文件被草稿引用，**只要草稿还在剪映里，就不能删**。真要清空间，先在剪映里导出成片、删掉草稿，再回来删这两个目录。
> **另注意**：这两个目录**不上传 GitHub**（在 `.gitignore` 里），但本地必须留着。

## 六、仓库里为什么没有这些文件

第一次 `git clone` 下来会发现东西很少，这是有意的：

| 没进仓库的 | 原因 |
|---|---|
| `.venv/` | 本机专用的运行环境，别人机器上无效；`install.bat` 会自己建 |
| `uploads/` | 视频素材，**含他人直播内容有版权风险**，且体积远超 GitHub 限制 |
| `preview/` | 每次生成都会重新产出的图片和清单，不是源码 |
| `demo/` | 15 秒测试素材，跑一次 `gen_demo.py` 就能重建 |
| `__pycache__/` | Python 字节码缓存，自动重建 |

> 判断标准：**能被一条命令重新生成的，都不进仓库。** 这些规则都写在 `.gitignore` 里，正常 `git add .` 不会误传。

另外为了跨平台兼容，文件名已全部改成 ASCII（中文名在 Mac/Linux clone 后会乱码，URL 里也会变成一长串 `%E5%88%87...`）：

`start.bat` / `start-cli.bat` / `fix-audio.bat` 是三个入口，两份 HTML 手册和两份 md 放在 `docs/` 下。

## 七、还想省空间的话（按性价比排）

| 做法 | 省多少 | 代价 |
|---|---|---|
| 成片导出后删 `uploads/` 里的原片 + clean 版 | 通常是几百 MB（原片 + 它一半左右的副本） | 想换一段重新剪，得重新拖入原片，并重跑一次抹字幕（5 分钟片约 100 秒） |
| 在剪映里清掉回收站里的旧草稿 | 草稿文件夹本身很小 | 无法恢复。**注意别把还想留的项目一起永久删掉** |
| 删 `.venv/` | 约 200 MB | **工具直接跑不起来**，得重跑 `install.bat`。不建议 |

## 八、一次完整操作会碰哪些文件（便于对照）

```
你拖进来的            →  uploads/原片.mp4 + 原片.srt
点「生成」时          →  clean_subs.py 产出 uploads/_clean/原片-clean.mp4（首次，约 100 秒）
                         markers.py 产出 uploads/_markers/x.xs_提示.wav
                         slice_by_text.py 算出切点、在剪映草稿目录建好草稿
                         suggest.py 产出 preview/草稿名-配乐清单.html
                         preview.py 产出 preview/草稿名.jpg
去剪映                →  打开草稿 → 对照配乐清单加音效/花字/BGM → 删掉「施工标记」轨 → 导出
```
